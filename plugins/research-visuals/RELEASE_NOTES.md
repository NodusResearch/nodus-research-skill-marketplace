# Research Visuals 1.1.0

Historical Maps can now build the map it was asked for, and says what that map is made of.

Until now a historical map needed a source whose period covered the request and an evidence URL, so a researcher asking for a dated map without a dataset in hand got a refusal — and the lane that stayed open, a model drawing its own map on the SVG canvas, produced exactly the figure this Skill exists to prevent. The map was wrong in a way no rule could see, because the Skill never ran. The line now runs between what is sourced and what is reconstructed, not between sourced and refused, and both render.

- **Supplied and dated.** A source that declares a period covering the requested interval and carries an evidence URL still produces a dated map, reported with that period.
- **Reconstructed.** Geometry and coordinates supplied for the request — the shape of a region, the places an itinerary names — render with a visible warning notice and an explicit approximate-reconstruction paragraph in the same view, so the label travels with the map into any document that embeds it.
- **Administrative divisions, drawn as a reference frame.** Provinces, regions and states are usually asked for by name and published only as today's map. A provider query is now accepted here as a reference layer: it is drawn and attributed, it never makes the map dated, and the result states in the map that those are today's boundaries rather than the period's. When the period's own division differs from the current one, the answer is supplied dated geometry or a labelled schematic reconstruction.
- **Routes and places are first class.** Markers and routes (`straight`, `curved`, `great-circle`, with optional arrow, colour and label) need no polygon layer: a request for a route between two named places is a map, not a special case.
- **What is still refused.** An opaque dataset handle in place of geometry, and a declared source period that does not cover the requested interval — the second because a label claiming a dating the source cannot support is the one failure that makes the rest dishonest. Label, attribution and licence remain required of every source.

**Compatibility.** This release installs on Nodus 5.6.0 and newer. The dated lane draws from a provider the application gains in 5.6.1: on a build without it, an `openhistoricalmap` query is refused with that reason and the map falls back to supplied geometry or a stated reconstruction, which is the behaviour on every other build. Raise this package's minimum to 5.6.1 when that version ships.

Historical Maps now draws the period's **own** divisions from OpenHistoricalMap: an `openhistoricalmap` query with a level (2 for states and polities, 4 for regions) and the requested period retrieves the boundaries whose own dates cover it, inside the request's bounds, and reports the period in the result. The adapter fails closed on an unreviewed per-element licence, on an element with no start date, and on geometry that exceeds the request limits, and it never substitutes another source.

A map request answered by hand is retired. A model that concludes the tool cannot help will draw the map itself, and that drawing is the one thing this Skill exists to prevent: it looks like a map and cannot be checked. The package now declares a `prepare` chat hook that claims the drawing lane when a cartographic question was answered with an SVG block of its own, which retires that block and leaves a notice saying what to do instead. A diagram beside a map request is left alone, and a map request answered through the tool has nothing to retire.

The schemas, limits, call ceilings, artifact contract and provenance exports are otherwise unchanged, and `render-map` still carries no dated request. **One new permission is requested**: retrieval from `openhistoricalmap`, on top of `natural-earth` and `geoboundaries`. The endpoint is a single public HTTPS host (Overpass) with no credentials, and the dataset is CC0 except for individual elements carrying their own licence, which the adapter refuses rather than assumes.
